## 3. 明确「不修」的发现（附原因）

宁缺勿滥：以下都真实存在，但修复收益/风险比不合适，**故意不动**，留档备查。

| 发现 | 为什么不在这一轮改 |
|---|---|
| T2' 部分翻译（translatedCount < total）仍写 `.done`，没有"继续翻译"入口 | 改成"不写 done"会让用户直接失去已翻出的半成品轨（当前 UI 已有 `x/y` 覆盖率 toast）。正确做法是 UI 区分"部分完成/可续翻"，属于功能设计改动，单独一轮做 |
| T3 B 站字幕恒为嵌入式 SRT（`isUrl()==false`），被候选过滤 → B 站视频没有双语按钮 | 需要新增"嵌入式字幕转 VTT"分支，是新功能不是 bug 修复 |
| T5 缓存键不含 baseUrl/appId；改 key 后需 bump CACHE_VERSION，会让所有人重翻 | 影响面大，建议以后专门做一次缓存键迁移 |
| T7 备份 zip 内含明文 API key（`preferences.all`），`allowBackup` 无排除规则；日志含 baseUrl/错误正文 | README 已明确"备份所有设置"是设计；剔除 key 会改变恢复语义（恢复后要重填 key）。安全加固应和"备份加密"一起评估 |
| T4 `deOverlapCues` 对人工轨同起点 cue 只留最长一条（可能丢整句） | 只影响人工字幕轨的重叠 cue；改它会让人工轨的堆叠渲染行为变化，需要真机验证 |
| BK-3 云恢复不校验 zip、先删旧库再写、失败无回滚（手动导入有校验） | 修复涉及 `ContentSettingsManager` 共享路径 + 原子替换，改动面大于本轮收益；建议单独做并加恢复前自动备份 |
| BK-4 偏好 `onPreferenceChange` 在值落盘前触发（关闭自动备份后仍可能上传一次，切 S3 后字段不切换） | 观感/时序问题，需要重构监听时机 |
| S3-1 生词本整本 JSON 每次全量解析（4n 次放大） | 纯性能，改读写路径不影响正确性；建议后续用一次性批量读取接口重构 |
| U6 未预检查"安装未知应用"权限；U8 403/超时文案不区分；U9 Downloads 副本堆积；U10 FileProvider 暴露面过大 | 体验/卫生项，非功能故障 |
| R-02 改完样式对正在播的视频不生效（需切轨/换视频） | 3 行可修，但会改玩家热路径（每次 cue 回调读 prefs），本轮不混入 |
| R-04 点词命中后吞掉整条手势（滑动调亮度/长按倍速等） | 现有设计取舍，误触与功能可用性的平衡，建议保持 |
| 0058 小窗恢复"掉帧"复核 | `removeViewFromParent/addView` 必然重建 Surface，现有三处改动不可能消除掉帧；`configChanges` 是全局行为改变。要真解决需要改 Surface 复用，风险高，建议后续单独立项 |
